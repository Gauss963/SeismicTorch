\begin{abstract}
This project classifies short three-component seismic waveforms into P waves,
S waves and noise, with an emphasis on QSIS MEMS acceleration recordings in
Taiwanese buildings. The revived implementation retains a compact waveform
CNN with convolutional channels $16\rightarrow32\rightarrow64$ and a classifier
$384\rightarrow64\rightarrow16\rightarrow3$. It contains 33,795 trainable
parameters and consumes two-second, 40 Hz waveform windows; spectrograms are
used only for diagnostics. The work includes GPU training on Apple MPS,
shared preprocessing, recording/event-aware evaluation, model-blind waveform
reference review and dependency-light native deployment.

The initial prepared-archive experiment reached 94.14\% on the STEAD test
archive but only 70.97\% on the QSIS test partition. These results motivated
arrival-window review, Taiwan strong-motion adaptation, training-only hard
background examples, data augmentation and per-record gravity alignment.
The released model was fitted for 20 epochs on 226 source windows initialized
from a six-epoch CWA adaptation run. An instrumented replay reproduces all
27 saved state tensors exactly and supplies the missing training curves.

On a newly acquired IES archive, the unchanged model correctly classified
27/27 agreed phase/background references at their centers and 26/27 after a
$+0.2$ s shift. Two prespecified primary cohorts together scored 44/44 at
center across 21 dates. Including three supplemental array-context references
produced 46/47 (97.87\%) at center and 45/47 (95.74\%) at $+0.2$ s. These are
conditional clip-classification results based on independently obtained,
model-blind AI visual references, not analyst-certified arrival labels or
continuous-stream detection accuracy. Limited sample size and unresolved
phase slots prevent a population-wide 95\% guarantee.

A C++17 implementation embeds the model constants, reads SAC or miniSEED and
returns three same-length probability vectors. All 141 reference-window
predictions match Python, with maximum absolute probability error
$4.17\times10^{-7}$. GitHub CI builds, tests and publishes Linux x86\_64/ARM64, macOS and
Windows executables under tag v1.0.0. A separate post-release sensitivity study completes 60 fits on date-grouped
training-pool folds, comparing two, three and four convolutional layers and
five QSIS epoch budgets. Additional depth shows no robust timing advantage;
longer fine-tuning gives modest validation gains while retaining a
fitting/validation gap. All figures in this report are PDF files.
\end{abstract}

\section{Introduction and project scope}
\subsection{Motivation}
Dense, inexpensive three-component sensors can support the observation of
building response and local earthquake shaking. QSIS recordings are a useful
application domain because an indoor MEMS sensor sees not only regional
seismic motion but also structural amplification, changes in installation
orientation, quantization, transient interference and channel faults. A model
trained on a general seismic archive cannot be assumed to transfer unchanged
to these conditions. Prior work on phase detection and tinyML demonstrates
why compact learned waveform representations are relevant to this setting
\cite{10.1785/0120180080,10.1785/0220220322}.

The concrete objective here is three-class recognition of an already selected
short window. The project also provides a sliding-window interface for
continuous recordings. It does not establish event association, earthquake
location, warning lead time, structural damage assessment or an operational
false-alarm rate. Those applications require additional labels and downstream
validation. In particular, assigning a high P probability to a window does not
by itself establish the arrival time of its first P sample.

\subsection{Questions addressed in the restart}
The restart addressed four implementation concerns: model dimensions, use of
GPU training, lack of code organization and an incomplete C++ inference path.
The verified architecture has three convolutional and three fully connected
layers. The numbers 16, 32 and 64 are \emph{output channel counts}; every
convolution uses a $3\times1$ kernel. They should not be confused with kernel
sizes or temporal pooling dimensions. SpectrogramCNN is outside the retained
workflow. Training uses CUDA when available, otherwise Apple MPS, otherwise
CPU; the retained QSIS checkpoint was trained on MPS.

The active Python code is now organized into model, data, training, inference
and QSIS review modules. Historical scripts and artifacts remain available
under \code{legacy/} and \code{reports/legacy/}. The native implementation lives
under \code{cpp/}; the old Xcode prototype has been preserved separately at
\code{legacy/cpp/}. This report documents the retained model rather than treating
every exploratory experiment as a production change.

\section{Datasets, provenance and reference construction}
\subsection{Prepared archives and the initial baseline}
STEAD is a public collection of three-component earthquake and noise signals
\cite{8871127}. The local experiment uses prepared arrays derived from that
resource, not the complete global dataset. Shape checks, finite-value checks,
one-hot target validation, joint amplitude normalization and duplicate
screening precede fitting. Identical normalized training inputs are collapsed;
groups containing inconsistent labels are removed. The archived arrays lack
full source-event metadata, so the initial STEAD split is not an independently
verified event-disjoint split of the full upstream archive.

The local QSIS array contains adjacent P/S windows from each event recording
followed by noise windows. The baseline groups paired P/S windows by recording
before splitting. This prevents the same recording's P and S examples from
being assigned to separate partitions, but does not guarantee that different
stations recording one earthquake stay in the same partition. This baseline
is therefore distinct from the later event/date-separated confirmation work.

\subsection{Taiwan strong-motion adaptation}
The CWA Benchmark resource supplies TSMIP acceleration recordings at 200 Hz
and trace metadata \cite{cwaData}. The retained adaptation experiment uses the
2011 chunk and matching published sample metadata. It checks the component
order (ZNE), sampling rate, acceleration measurement, completeness flag,
single-event status and the metadata's manual-pick status, including the
published misspelling \code{maunal}. Accepted traces must be finite, have
nonconstant axes and leave sufficient context around the P and S references.

Exactly 2,748 traces survive. Each supplies P, S and pre-P background windows,
for 8,244 examples, balanced at 2,748 per class. Raw axes are reordered to ENZ.
The adaptation path detrends and tapers the complete trace, high-pass filters
at 0.5 Hz at its native rate and downsamples to 100 Hz before producing model
windows. This historical CWA preparation differs from the final QSIS
steady-start route; it is not silently described as identical preprocessing.

A seeded event split assigns 292 earthquake IDs to fitting and 73 to
validation. The resulting partitions contain 6,507 and 1,737 clips,
respectively. The chosen adaptation checkpoint is epoch 6, with validation
balanced accuracy 97.99\%. It is an initialization resource, and its validation
score is not a QSIS test result. The 2011 source period precedes the later QSIS
evaluation recordings.

\subsection{Final QSIS fitting pool}
The released checkpoint uses 226 ordered source windows: 33 P, 47 S and 146
noise windows. This pool combines the earlier 219-source recipe and seven
additional agreed CCUL training phases. It includes visually reviewed phases,
screened training proposals and background examples selected on training
dates. Proposals serve as weak training targets and are not promoted to
independent evaluation labels. Every source in the receipt records its paths,
center, target and group identity. The pool contains 63 distinct group
identifiers; event identifiers and noise-date identifiers have different
meanings and should not be interpreted as 63 independent earthquakes.

The predominance of noise windows motivates reciprocal-frequency class
weights. Per-record gravity alignment is usable for 104 fitting windows; the
remaining 122 retain the acquired axes. There is no station calibration table
in the released receipt. Training examples are not supplemented with any of
the fresh IES test clips. Figure~\ref{fig:composition} shows the class counts
and the exact composition of the confirmation references.

\subsection{Prespecified primary confirmation}
The earlier primary confirmation cohort contains 17 scored references across
nine UTC dates: 3 P, 5 S and 9 pre-event backgrounds. Station/date enrollment
and model identities were fixed before target waveform review and scoring.
Nearby P-Alert recordings provide context, while the reference time is read
from the target QSIS waveform. Two independent model-blind AI reviewers
supply the waveform judgments. Of 36 enrolled phase slots across 18 dates,
eight yield agreed usable phase references. The unresolved slots are retained
in the coverage accounting rather than assigned convenient targets.

Additional array context later supports three more references on the reserved
dates: two P and one S. These are reported as a supplemental extension of the
17-clip set, giving 20 earlier references in total. Their review procedure is
still model-blind, but they are separated from the original primary enrollment
to preserve the distinction between prespecified and follow-up evidence.

\subsection{Fresh IES archive confirmation}
The IES Building Seismic Response Dataset was published on Zenodo in October
2025 and combines legacy SMA-1 and QSIS recordings \cite{iesData}. The local
archive inventory contains 3,069 QSIS SAC components, 112 event identifiers
and 64 event dates. The download is 225,569,391 bytes and matches the
publisher's MD5, \code{d0e9eef37f0844e349623174984ca8ea}. The original files
remain unchanged. The source supplies waveform/event metadata, but no usable
QSIS P/S analyst-arrival file was found in it.

Fifteen dates remain after excluding the original split, all candidate fitting
dates and all earlier public evaluation cohorts. Before visual inspection,
enrollment selects the largest listed earthquake per date, the two lowest
complete instrument codes as targets and up to two additional instruments as
context. Inputs must be aligned 100 Hz XYZ triplets with at least 30 seconds
before origin and 120 seconds afterward; nearby previous events are excluded
using a 120-second embargo. Catalog/SAC clock consistency is checked. Missing
station coordinates are supplied from the archive's documented IES location,
with that substitution recorded.

There are 29 enrolled target recordings, hence 58 possible P/S phase slots.
One target fails raw waveform QC, leaving 28 rendered targets. Two independent
AI readers examine the target waveforms in three bands, local array energy
and a wider overview without seeing classifier outputs. Agreement within
0.6 s yields nine P and six S references across six event dates. The other
41 rendered phase slots remain unresolved; the failed recording contributes
two additional QC-excluded slots. This is 15 agreed phase slots out of 58
enrolled, not an assumed 58/58 fully labelled benchmark.

Backgrounds are selected separately. A CWA catalog screen removes candidate
centers near regional catalog origins, and the maximum eligible 1 s / 5 s
STA/LTA peak is chosen in a prespecified pre-event interval. Raw dropouts and
inadequate filter/context support are excluded. Two readers accept 12 of 14
rendered background candidates, leaving a staircase-like quantized signal and
a disputed transient unresolved. The final fresh cohort is 9 P, 6 S and 12
noise clips on 12 dates. Figure~\ref{fig:coverage} makes the selection coverage
explicit.

\section{Waveform preprocessing and input representation}
\subsection{Synchronization and acquired-axis QC}
The verified Python route expects synchronized 100 Hz acceleration traces in
X, Y, Z order. All components need the same start, rate and sample count.
Missing or nonfinite data are rejected by the single-window Python interface.
The dense native interface instead splits finite segments and fills
unscorable output positions with NaN.

A center $c$ at 100 Hz uses samples $[c-100,c+100)$, giving exactly 200 raw
samples per component. A one-second repeated run in any \emph{acquired} axis
invalidates the window. This test precedes physical rotation: rotating a
constant or failed channel could otherwise mix motion from healthy axes into
it and conceal the fault. A zero or nonfinite normalization peak is also
invalid. Full two-second support is mandatory.

\subsection{Detrending and the steady-start high-pass filter}
Each complete finite recording is linearly detrended in double precision.
For a component $x_i$, the fitted line is $a+bi$, where $a,b$ minimize the
squared residual. A fourth-order Butterworth high-pass filter at 0.5 Hz is
applied as two second-order sections. Instead of tapering the beginning of a
recording, the released QSIS path uses steady initial conditions obtained
from \code{sosfilt_zi} multiplied by the first detrended sample. This avoids a
taper amplitude ramp while preserving the selected training/inference route.
The filter is causal, but whole-record detrending uses later samples. The
current file-based pipeline is therefore \emph{not} a strictly online causal
picker; streaming deployment would require a separately validated detrending
and state-handling design.

\subsection{Gravity-derived rotation}
Stable gravitational offsets can identify the vertical axis of a stationary
acceleration sensor. The algorithm computes one-second component medians over
seconds 1--7, then a componentwise median across those six blocks. Let that
baseline be $\mathbf{g}$ and its normalized direction be
$\mathbf{u}=\mathbf{g}/\|\mathbf{g}\|$. Alignment requires a magnitude between
900 and 1,100 gal and a maximum block-vector drift of at most 8 gal, where
$1\;\mathrm{gal}=1\;\mathrm{cm\,s^{-2}}$. The shortest proper rotation maps
$\mathbf{u}$ to the positive vertical axis. If the baseline is unusable, the
identity transform is retained.

For $\mathbf{v}=\mathbf{u}\times\mathbf{e}_z$ and
$d=\mathbf{u}\cdot\mathbf{e}_z$, the nondegenerate rotation can be written
\begin{equation}
 R=I+[\mathbf{v}]_\times+
 \frac{[\mathbf{v}]_\times^2}{1+d},
\end{equation}
with explicit parallel/antiparallel handling. Alignment is applied only from
center sample 800 onward, so the six-second baseline precedes the complete
classification window. It determines vertical orientation, not geographic
azimuth; it cannot establish north/east directions from gravity alone. There
is no station-name fallback in the deployed model.

\subsection{Fourier resampling and joint normalization}
After filtering and, when applicable, rotation, a 200-sample cut is
Fourier-resampled to 80 samples per axis. At 40 Hz this remains a two-second
window. All components share one peak scale:
\begin{equation}
 \widetilde{x}_{t,a}=
 \frac{x_{t,a}}{\max_{t',a'}|x_{t',a'}|},
 \qquad t=0,\ldots,79,\quad a\in\{X,Y,Z\}.
\end{equation}
The tensor supplied to PyTorch has shape $[B,1,80,3]$ in float32. Joint
normalization preserves relative component amplitudes, although it removes
absolute amplitude. Figure~\ref{fig:examples} shows both acquired deviations
and the actual normalized model inputs for representative held-out clips.

No time-frequency image is supplied to this classifier.
Figure~\ref{fig:spectral} is an explanatory diagnostic calculated from the
same reference waveforms; it does not change the inference representation.
The class spectra describe this small selected sample and do not establish a
universal spectral boundary between phases or between buildings.

\section{CNN architecture}
Figure~\ref{fig:architecture} summarizes the retained processing chain.
Convolutions have unit stride, no padding and $3\times1$ kernels. Temporal
max pooling has kernel and stride $3\times1$. Thus early convolutions share
temporal filters across the three physical components without convolving
across the component dimension. The flattened fully connected stage combines
those component-specific feature responses.
\fig[Preprocessing and retained CNN architecture]{pipeline_architecture}{1}{Released preprocessing and CNN. Output
channels are 16/32/64; temporal pooling reduces 80 model samples to two time
positions. The final feature volume is $64\times2\times3=384$.}{fig:architecture}

The exact GELU is $x\Phi(x)$, with $\Phi$ the standard normal cumulative
function. Softmax maps logits $z_k$ to
$p_k=\exp(z_k-m)/\sum_j\exp(z_j-m)$, $m=\max_jz_j$. Class order is always
P, S, Noise, corresponding to indices 0, 1, 2. Dropout is disabled and BN
uses stored running statistics at evaluation. A longer-input research path
contains adaptive pooling, but the selected checkpoint and native port use
exactly 80 input samples and need no adaptive-pooling operation.

\section{Training recipe and recorded learning curves}
\subsection{Initial prepared-archive training}
The saved initial STEAD run uses MPS, PyTorch 2.11.0, seed 42, batch size 256,
50 epochs and Adam with learning rate $10^{-3}$. StepLR halves the learning
rate every seven epochs. Validation selects epoch 25, rather than assuming
the final epoch is best. The held-out prepared archive then scores
16,426/17,449. Figure~\ref{fig:stead} reproduces the original epoch log.

The initial QSIS archive fine-tuning starts from that STEAD checkpoint,
uses AdamW, batch size 32, 100 epochs, initial learning rate $10^{-3}$ and
the same seven-epoch schedule. Validation selects epoch 10. The test score is
176/248, with substantial P/S confusion. Figure~\ref{fig:qsis-old} shows that
training accuracy keeps improving while validation largely plateaus. This
is evidence of a generalization gap, not a reason to report the training
accuracy as achieved QSIS accuracy. Its test partition is left separate from
the later reviewed references and their differently defined labels.
\fig[Prepared STEAD training and validation curves]{training_stead}{1}{Original 50-epoch prepared STEAD training log. The
vertical line marks the validation-selected checkpoint at epoch 25. Test
metrics are not evaluated at every epoch or drawn as a selection curve.}{fig:stead}
\fig[Initial QSIS training and validation curves]{training_qsis_baseline}{1}{Original 100-epoch QSIS archive fine-tuning.
The selected checkpoint is epoch 10. The fitting/validation gap and persistent
phase confusion motivate the subsequent review and adaptation work.}{fig:qsis-old}

\subsection{CWA adaptation}
The CWA stage initializes from the STEAD checkpoint, updates all CNN weights
using AdamW at $10^{-4}$, batch size 128, six epochs and seed 42. It applies
time-shift and horizontal-rotation augmentation to training batches. The
class balance is exact, so ordinary cross-entropy is used. Validation is
held out by earthquake identifier. All six recorded epochs are shown in
Figure~\ref{fig:cwa}; the retained epoch-6 checkpoint initializes the final
QSIS fit. Its checksum is recorded in Appendix~\ref{app:provenance}.
\fig[CWA adaptation training and validation curves]{training_cwa}{.97}{Six recorded CWA adaptation epochs. Validation is
held out by CWA event ID and measures the adaptation domain. It is not the
independent QSIS confirmation set.}{fig:cwa}

\subsection{Released QSIS fine-tuning}
The final fit updates all layers for a fixed 20 epochs with seed 42 on MPS.
Batch size is 16; AdamW uses learning rate $3\times10^{-4}$ with its default
weight decay 0.01, betas $(0.9,0.999)$ and epsilon $10^{-8}$. There is no
learning-rate scheduler in this final fit. The last epoch is retained; the
fresh test is not used to select an epoch.

Training augmentation reflects time indices at the clip boundaries rather
than wrapping them. Each example receives an integer shift from $-8$ to $+8$
at 40 Hz (up to $\pm0.2$ s), and a horizontal rotation uniformly drawn from
$\pm30^\circ$. The vertical axis remains unchanged, and joint peak
normalization is reapplied. These transformed inputs are training views of
the same 226 source windows; they do not increase the number of independent
source recordings.

Reciprocal-frequency class weights $w_k=1/n_k$ enter weighted cross-entropy:
\begin{equation}
 L_{\mathcal{B}}=
 -\frac{\sum_{i\in\mathcal{B}}w_{y_i}\log p_{i,y_i}}
         {\sum_{i\in\mathcal{B}}w_{y_i}}.
\end{equation}
The existing epoch logger weights these batch means by batch size before
averaging. Because class weights and batch compositions vary, that logged
training objective is not mathematically identical to one weighted reduction
over the entire epoch. The clean fitting-set diagnostic uses ordinary
unweighted cross-entropy. Figure~\ref{fig:final-fit} labels the two loss
reductions explicitly; their numerical gap should not be interpreted solely
as overfitting.

\subsection{Recovery and verification of the missing final curves}
The original final fitting function saved weights and source receipts but no
per-epoch history. To recover truthful curves, the reporting utility reloads
the 226 source paths/centers in their recorded order and reruns the existing
fitting function with the same initialization, seed, device, augmentation and
optimizer. A wrapper records each existing epoch result and evaluates only
the clean \emph{fitting} inputs in evaluation mode. CPU and MPS random states
are preserved around the diagnostic. No validation or test reference is read
by this replay.

After fitting, every state tensor is compared with the released checkpoint
using exact tensor equality. All 27 tensors match. The curves are therefore
an instrumented exact replay of the released weights, not fabricated or
smoothed estimates of an unavailable training log. The clean fitting score
at epoch 20 is 224/226 (99.12\%); the online augmented training score is
222/226 (98.23\%). These remain training scores. A high fitting score alone
cannot demonstrate freedom from overfitting.
\fig[Exact replay of the final 20-epoch fit]{training_final}{1}{Exact 20-epoch replay of the released final fit.
Blue curves are online augmented training metrics with dropout active;
orange curves evaluate the unaugmented fitting inputs after each epoch with
dropout disabled and stored BN statistics. There is no test/validation curve
for this final refit. All 27 saved state tensors reproduce exactly.}{fig:final-fit}

\subsection{What constrains overfitting}
The project uses transfer initialization, a small model, dropout, weight
decay, class weighting, training augmentation, event/date exclusions and
separate confirmation cohorts. Exploratory changes are evaluated on
development data. Larger networks are not adopted merely because their
training loss improves. Nonetheless, many development comparisons have been
made, and archived evaluation references were subsequently reused. They are
reported descriptively, rather than retrospectively relabelled as untouched
holdouts. The fresh cohort is the clearest additional confirmation because
both model identities and its enrollment protocol were fixed before its
waveform review.

\section{Sensitivity to model depth and training duration}\label{sec:sensitivity}
\subsection{Study design and separation from confirmation}
A post-release sensitivity study varies convolutional depth and the number
of QSIS fitting epochs. Its data are restricted to the 226 fitting sources
already recorded in the released receipt. None of the 47 independent
confirmation references is used to select an architecture, an epoch or an
initialization. This is development cross-validation on the existing fitting
pool, whose targets include reviewed and weak training labels; its scores
are not new independent confirmation accuracy.

To avoid recording/date leakage, source-event dates, SAC start dates and
center-sample dates are joined into connected UTC-date groups. This also
keeps an earthquake crossing midnight from being split through its start and
origin dates. The 226 sources form 58 such groups. An exact audit also finds
226 unique normalized centered inputs and no identical input shared across
validation folds. Five folds are frozen
before fitting. Their validation class counts (P/S/Noise) are $(7,10,28)$,
$(6,10,28)$, $(7,9,30)$, $(7,9,28)$ and $(6,9,32)$. Fold assignment is balanced
using target counts only, without inspecting predictions. Each validation
source is held out once per seed. A group's sources cannot appear on both
sides of its fold.

Three fixed fitting seeds, 42, 43 and 44, are paired across all configurations.
Every trajectory runs for 80 epochs, saving evaluations at epochs 5, 10, 20,
40 and 80. All configurations use the same source cuts, five folds, batch
size 16, AdamW learning rate $3\times10^{-4}$, weight decay 0.01, reciprocal
\emph{fitting-fold} class weights and original shift/rotation augmentation.
Raw evaluation windows are recut at $-0.2$, 0 and $+0.2$ s. Validation uses
evaluation mode and unweighted cross-entropy. No early stopping or adaptive
rerun is triggered by these validation measurements.

The study completes $4\times3\times5=60$ fits and 4,800 aggregate QSIS
optimization epochs, or 57,600 optimizer steps. This is the experiment-wide
budget, not the age of a single model. Predictions from all five validation
folds are pooled over 226 sources separately for each seed. Tables and plots
then report the mean and sample standard deviation across the three seeds.
The five folds and repeated timing views are not counted as independent
replicates to narrow an error bar. Seed SD is not a confidence interval.

\subsection{Meaning of total epochs and the retained model}
The varied epoch count is the final QSIS fitting duration, with preceding

improvement at 80 epochs is a useful development observation, not permission
to re-label the existing 47 clips as a new untouched test for an optimized
model. Any replacement should first be frozen and then confirmed on new
expert-labelled events and background periods. The 58-group training-pool
study does not remove its weak-label or single-network limitations.

\section{Evaluation protocol and statistics}
\subsection{Units, offsets and metrics}
The evaluation unit is one two-second reference clip. Its target is the
phase/noise category of a selected window, not a dense sequence of analyst
labels at every input sample. Each clip is re-cut from the raw recording at
center offsets $-0.2$, 0 and $+0.2$ s. Those three views are strongly related;
47 clips produce 141 evaluations, not 141 independent test examples.

Confusion matrices use reference classes as rows and predicted classes as
columns, in the order P, S, Noise. For matrix $C$, class recall is
$C_{kk}/\sum_j C_{kj}$ and precision is $C_{kk}/\sum_i C_{ik}$. Accuracy is
$\operatorname{tr}(C)/\sum_{ij} C_{ij}$; balanced accuracy averages class recalls,
and macro F1 averages the three class F1 scores. These definitions make the
minority P class visible even when noise dominates the overall score.

Report generation reopens each of the 47 references, applies the released
preprocessing and recomputes all 141 softmax vectors using the frozen model.
Every argmax prediction matches the saved comparison. The regenerated
matrices are also checked against the immutable evaluation receipt, so the
figures and tables use one consistent prediction source.

\subsection{Reference independence and coverage}
Two independently obtained model-blind AI reviews are separate waveform
judgments, but they are not seismologist-certified manual arrival files.
Agreement does not eliminate correlated visual interpretation errors. No
expert QSIS arrival catalog was supplied. References from unclear targets
are excluded from accuracy and counted explicitly, as in
Figure~\ref{fig:coverage}. The 0.6 s reviewer-agreement tolerance should not
be read as achieved arrival-time error by the classifier.

The combined primary sample has 44 clips across 21 dates; the three
supplemental references reuse those reserved dates and bring the total to 47.
Many phase clips share an event, building or recording. The reference counts
must therefore be accompanied by date/site coverage, not treated as a large
collection of independent random draws from all future QSIS observations.

\subsection{Uncertainty and the 95\% objective}
For transparency, Figure~\ref{fig:timing} includes ordinary 95\% Wilson
intervals treating clips as independent Bernoulli observations. For 46/47,
that illustrative interval is 88.89--99.62\%; for 44/44 it is approximately
91.97--100\%. Independence is an approximation because clips cluster by
UTC date and site. These intervals already show why the observed 97.87\%
point estimate is not a lower-bound guarantee above 95\%.

A second descriptive analysis resamples all clips jointly by UTC date,
using 10,000 seeded replicates over the 21 dates. It gives percentile
intervals 93.02--100\% at center and 89.19--100\% at $+0.2$ s for the
47-clip set. Resampling the observed dates cannot introduce unseen buildings,
unresolved reference types or unobserved failures. All-correct subsets can
also give degenerate bootstrap intervals. Neither calculation removes the
selection and label-coverage limitations.

Even under an ideal independent-binomial interpretation, 59 consecutive
correct trials would be required for a one-sided exact 95\% lower bound to
exceed 95\%, since $0.05^{1/59}>0.95$. A realistic QSIS study also needs
independent events, sites and noise conditions. This numerical illustration
is a study-design guide, not a claim that adding a few selected clips would
resolve the current evidence limitations.

\subsection{Recent primary literature}
PhaseNet established a dense three-component P/S arrival-probability approach
\cite{phasenet}. Its task differs from assigning one label to a selected
window. This distinction also applies to newer networks and prevents direct
comparison of a picking F1 score with QSIS clip accuracy.

DTPP (2026) combines depthwise separable temporal processing and dilations
for efficient phase picking \cite{dtpp}. Its relevance here is a compact
longer-context design principle. The local TCN experiment is inspired by
that general direction; it is not a replication of DTPP and the retained
CNN is not renamed as that architecture.

U-Trans (March 2026) pretrains a U-Net/convolutional-transformer waveform
representation by reconstructing corrupted inputs \cite{utrans}. It is a
reasonable candidate when transferable context representations are needed.
Our local comparison freezes its backbone and fits a regularized head on
small QSIS folds. The published framework also studies joint downstream
fine-tuning, so the local 35/41 comparison is evidence about this restricted
configuration, not a general refutation of foundation models.

PhaseNeXt was published on 4 November 2026 and studies a neural picker trained
on twenty years of JMA records \cite{phasenext}. Its ConvNeXt/multiscale context
and use of carefully checked small-event examples are relevant to future
QSIS timing work. A local timing pilot used the authors' pinned weights:
27 of 46 previously reviewed public arrivals passed the raw/band-pass
agreement filter, and 26 of those were within 0.6 s of the visual reference.
That is a proposal-quality diagnostic with incomplete retention, not 26/27
end-to-end QSIS phase classification accuracy. The earlier RED-PAN search
matched 36 references and the union matched 40; differing search windows
and preprocessing prevent an architecture-only comparison.

These sources support continued investigation of transferable context and
label quality. They do not establish that replacing a 33,795-parameter CNN
with a transformer will improve this small sensor-specific dataset. A useful
next comparison would freeze a new event/site test protocol, hold out expert
arrivals, match context availability and measure class recall, timing error,
continuous false alarms and CPU cost together.

\section{Standalone C++ inference and reproducible release}
\subsection{Public API and input decoding}
The C++17 project exposes standard-library types through
\code{cpp/include/seismictorch/inference.hh}. Three binary SAC v6/v7 files
are accepted in X/Y/Z order, including either byte order and the SAC v7
double footer. Component rates, UTC starts and sample counts must agree.
A whole miniSEED 2 or 3 file is decoded by a statically linked vendored
libmseed 3.6.0. Compressed Steim and supported numeric encodings are handled
without requiring a separately installed decoder at runtime.

miniSEED components are grouped by network, station, location and channel
family; XYZ, ENZ and 12Z suffixes map to the three axes. An ambiguous
multi-station file requires an explicit stream selector. Samples are aligned
to a common UTC grid. Gaps become NaN, while conflicting overlapping samples
are rejected. Files are limited to 2 GB and the aligned grid to 50 million
samples. Inputs need calibrated acceleration; the gravity check expects gal.
Instrument response removal and automatic unit inference are not performed.

\begin{lstlisting}[language=C++]
#include <seismictorch/inference.hh>

auto wave = seismictorch::read_sac({"X.sac", "Y.sac", "Z.sac"});
// Or: auto wave = seismictorch::read_mseed("recording.mseed");
auto scores = seismictorch::infer(wave);
std::vector<float> P = std::move(scores.p);
std::vector<float> S = std::move(scores.s);
std::vector<float> Noise = std::move(scores.noise);
\end{lstlisting}

Every vector has exactly the aligned input length. The default stride is one
sample, so every supported sample center is evaluated. The first/last
unsupported centers, nonfinite gaps, raw dropout windows and zero signals
remain NaN in all three vectors. They are not fabricated noise predictions.
Stride values above one explicitly request an approximation with interpolation
between valid anchors; they are not identical to dense inference.

\subsection{Raspberry Pi 5 / 64-bit ARM Linux}
The CI matrix now includes \code{linux-arm64} on the native GitHub
\code{ubuntu-24.04-arm} runner. Its Alpine/musl container builds with baseline
\code{-march=armv8-a} C/C++ flags, static standard runtimes and the same
embedded model. CI executes all four CTest checks natively on ARM64, verifies
the ELF AArch64 machine type and absence of a dynamic interpreter, then runs
an actual 1,400-sample miniSEED inference outside the build container.
This is execution verification, not only cross-compilation.

The target is Raspberry Pi 5 with 64-bit Raspberry Pi OS or another 64-bit
Linux distribution. No matching glibc installation is required. A 32-bit OS
cannot execute this package. Hosted ARM64 testing does not provide a
measurement of physical Pi 5 throughput, power use or thermal behavior.
The ARM64 archive is added to the existing v1.0.0 release together with an
updated four-package checksum file; the original three archives and tag are
retained. Future tagged CI releases automatically require all four builds.
The native ARM64 evidence is
\href{https://github.com/Gauss963/SeismicTorch/actions/runs/44905643313}{run 44905643313}.

\subsection{Embedded constants and numerical equivalence}
The Python exporter reads the verified checkpoint and training receipt,
checks the expected CNN/preprocessing and writes hexadecimal floating-point
constants to \code{cpp/generated/model_weights.hh}. Batch normalization is
folded into each convolution:
\begin{equation}
 W'_o=\frac{\gamma_o}{\sqrt{\sigma_o^2+\epsilon}}W_o,\qquad
 b'_o=\frac{\gamma_o(b_o-\mu_o)}{\sqrt{\sigma_o^2+\epsilon}}+\beta_o.
\end{equation}
The generated constants are committed, so normal CMake compilation requires
neither Python nor a model file. Convolutions, exact GELU, pooling, fully
connected layers and stable softmax execute directly on CPU. The native
program does not require PyTorch, LibTorch, BLAS or MLX at runtime.

The original verified preprocessing path is 100 Hz. Native rates 40--1000 Hz
are accepted by constructing the high-pass filter at the acquired rate and
resampling each two-second window to 80 model samples. Golden preprocessing
fixtures check 40, 50, 100, 200 and 1000 Hz; this is numerical implementation
verification, not an accuracy benchmark for every sensor/rate combination.

Full local parity uses 27 actual SAC recordings containing the 47 references,
recomputed at all three offsets. The native path includes SAC decoding,
detrending, high-pass initialization, gravity alignment, Fourier resampling
and the embedded CNN. All 141 decisions match Python; the maximum absolute
probability difference is $4.1723164\times10^{-7}$. Smaller CI fixtures carry
the same normalized model windows and independent preprocessing golden cases,
without transferring the full local waveform archives to every build runner.

\section{Limitations and next validation steps}
The retained model meets the numerical 95\% objective on the scored,
independently reviewed confirmation references at all three fixed offsets.
That statement has a defined denominator and should remain attached to it.
The following limits materially affect interpretation:
\begin{enumerate}
\item \textbf{Reference quality.} No analyst-certified QSIS arrivals were
available. AI visual agreement is useful audit evidence but cannot replace
external seismological annotation for a deployment claim.
\item \textbf{Partial phase coverage.} Only 15 of 58 newly enrolled phase
slots are agreed/scored. Excluding unclear examples makes the task
conditional on readability; unresolved examples cannot be assumed correct.
\item \textbf{Sample size and dependence.} Forty-seven clips on 21 dates
remain small and correlated. The illustrative uncertainty bounds extend below
95\%; all-correct subsets provide little information about rare failures.
\item \textbf{Domain coverage.} The new archive emphasizes magnitude-5-or-
larger earthquakes at one building. Other buildings, weaker arrivals,
instrument changes and long quiet periods need independent coverage.
\item \textbf{Historical reuse.} The 215 archived references and many
exploratory comparisons have informed development. Their scores are not
fresh final-test evidence.
\item \textbf{Task mismatch.} Clip accuracy does not measure pick timing,
event-level detection, missed-event rates or false alarms per hour. A
continuous stream contains many overlapping windows and many more background
opportunities than the confirmation clips.
\item \textbf{Temporal availability.} Centered windows require later samples,
gravity estimation needs a stable preceding baseline, and whole-record
linear detrending is offline. A causal runtime would need its own training
and validation protocol.
\item \textbf{Probability interpretation.} Softmax values have not been
independently calibrated. A high maximum value is not a guaranteed
probability of correctness under a new sensor distribution.
\end{enumerate}

The next study should obtain expert references, freeze event/site-disjoint
training/validation/test groups, document all unscorable intervals and
annotate continuous background hours. Thresholds and debounce logic should
be selected on validation only. The final test should report per-class
recall/F1, event-level sensitivity, matched-arrival timing error, false alarms
per hour, CPU throughput and unavailable-output coverage. A transformer or
multiscale replacement should be compared on exactly those same frozen
inputs and resource constraints. Additional training should be motivated by
those failures rather than tuning against the present confirmation cases.

\section{Conclusion}
The restart turns the original prototype into a reproducible waveform
classification and native inference project. The retained architecture is
verified as a 16/32/64-channel CNN with a 384/64/16/3 classifier, trained on
Apple MPS and reproduced exactly after code reorganization. The report
preserves the weak early QSIS baseline and documents how stronger
arrival-reference review, regional adaptation and preprocessing discipline
led to a final 46/47 centered extended-confirmation score. The 45/47 positive-
offset result and two P-to-S failures remain visible.

The standalone v1.0.0 release embeds the selected weights and provides tested
SAC/miniSEED inference on Linux, macOS and Windows. Numerical agreement with
Python is established on all 141 fixed-offset evaluations. The date-grouped sensitivity study does not support increasing depth merely
for a small centered gain. An 80-epoch QSIS fit is a development candidate
for further confirmation, while the released 20-epoch weights remain fixed.
The next research
priority is a larger expert-labelled, event/site-separated and continuous
QSIS benchmark, so the observed clip-level result can be tested against the
broader reliability requirements of real deployment.
